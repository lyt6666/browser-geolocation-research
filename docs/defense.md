# 防御方视角：识别与反制定位追踪

> 定位追踪的「攻」和「守」是一体两面。本文件从**防御者**角度，教你识别异常定位请求，并系统性反制。

---

## 1. 识别信号：一个页面「想定位你」的迹象

### 1.1 权限请求本身

任何浏览器定位请求，都会在地址栏/通知栏留下痕迹：

- **桌面浏览器**：地址栏出现定位图标（📍），点击可见「是否允许此站点访问位置」。
- **移动端**：系统弹「此网页想要使用你的位置」授权框。

**红线信号**：一个你只是「随便逛逛」的陌生站点，突然索要位置权限 —— 这本身就是异常。正常内容站（新闻、购物、查资料）极少需要你的**精确**位置，最多要个城市（走 IP 即可）。

### 1.2 证书与传输异常

| 信号 | 含义 |
|---|---|
| 陌生域名 + 无证书/自签证书警告 | 刻意规避「HTTPS 才能定位」的门槛 |
| 已 HTTPS、却仍提示证书不受信任 | 自签证书，用于过 secure context 但不被 CA 认可 |
| 短链/跳转链（cpolar、内网穿透域名） | 临时性、随机子域，隐蔽真实来源 |

### 1.3 页面行为异常

- 无实质内容，却抖屏/弹权限/催你「点允许」
- 大量请求 `navigator.geolocation`、`getUserMedia`（摄像头/麦克风）、传感器
- 页面标题/内容与 URL 完全对不上

## 2. 反制手段

### 2.1 浏览器级（最有效）

| 平台 | 操作 | 效果 |
|---|---|---|
| **仅允许/阻止** | 地址栏定位图标 → 「阻止」 | 该站点永久拿不到位置 |
| iOS Safari | 设置 → 隐私 → 定位服务 → Safari → **关闭** | 一刀切 |
| Chrome（桌面/安卓） | 站点设置 → 权限 → 位置 → **禁止** | 单站点禁止 |
| Firefox | about:preferences → 隐私 → 权限 → 位置 → 阻止 | 全局/单站 |

### 2.2 网络级（抹掉 IP 归属维度）

- **VPN**：隐藏真实出口 IP（位置追溯退化为「VPN 服务器所在城市」）
- **Tor**：更强的匿名，但注意出口节点仍可被 GeoIP 归于某国
- 关闭 Wi-Fi：屏蔽 Wi-Fi 热点定位维度（但移动数据下仍有基站定位）

### 2.3 系统级（切断定位服务）

- 关闭系统「定位服务」总开关 → 浏览器即使授权也拿不到坐标
- 关闭蓝牙（部分室内定位依赖蓝牙信标）

### 2.4 行为级

- 陌生链接、短链、来路不明的「投票/抽奖/查信息」页 → 一律不点
- 弹出权限请求时，「以后再说 / 拒绝」是默认不亏的选择
- 用**隐身窗口**访问不明站点（无痕模式默认要求每次授权）

## 3. 技术视角：定位到底暴露了什么

防御者要明白，定位请求成功 = 对方拿到：

```
你的精确坐标（WGS-84，精度 10 米级）
    +
你的设备指纹（UA / 分辨率 / 语言 / 时区 / WebGL ...）
    +
你的网络画像（出口 IP 归属 / 连接类型）
    =
可交叉关联的「你是谁 + 你在哪 + 你用什么设备」
```

**核心认知**：单独一项坐标没多大价值，但和指纹交叉后，即可构建高度指向性的个人画像。这就是为什么「拒绝定位权限」不够，还要配合「减少指纹暴露」。

---

## 4. 开发与安全从业者的口令

- 你写的每个页面里，`navigator.geolocation` 出现时，问自己：**这个功能真的需要用户精确位置吗？** 城市级用 IP 归属就够了。
- 需要定位的产品，明确告知用途（导航、本地服务），并允许用户随时撤销。
- 合规：GDPR、个保法下，**精确位置属于敏感个人信息**，未经明确同意不得采集、不得外传。

---

## 5. 一句话总结

**米级定位的防御核心，不是「技术对抗」，而是「权限纪律」** —— 陌生站点要位置，永远先拒绝；真正需要的定位，你自己会主动给。
