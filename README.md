# 浏览器地理定位与设备指纹技术研究

一份关于**浏览器如何获取设备位置与指纹**的技术研究笔记，重点剖析**米级地理定位**的完整链路。

> ⚠️ **用途声明**：本仓库为**技术原理研究与防御学习**用途。所有内容仅用于理解浏览器隐私暴露机制，从而更好地**保护自己、识别风险**。不含任何真实采集数据、不含摄像头/麦克风采集代码、不提供一键部署的追踪/钓鱼工具。

---

## 定位精度分级

浏览器（以及现代 Web 应用）获取位置信息的精度，大致分四个层级：

| 层级 | 精度 | 数据来源 | 是否需要授权 |
|---|---|---|---|
| **国家级** | ~ 城市/省份 | 出口 IP 反向解析（GeoIP） | 否 |
| **城市级** | ~ 数公里 | IP 库 + 运营商路由 | 否 |
| **百米级** | ~ 百米 | Wi-Fi 热点三角定位、基站（Cell Tower） | 系统定位服务 |
| **米级** | **1–30 米** | **GPS/GNSS 卫星 + 辅助定位（A-GPS）** | 用户明确授权 |

本仓库聚焦最后一级：**米级地理定位**。

---

## 米级定位的三要素

浏览器拿到米级坐标，本质是「**安全上下文 + 用户授权 + 定位硬件**」三者齐备后的结果：

```
① Secure Context（HTTPS / localhost）
        │  浏览器只在安全上下文里允许访问定位 API
        ▼
② 用户主动授权（浏览器弹窗「允许/拒绝」）
        │  navigator.geolocation 触发权限请求
        ▼
③ 系统定位服务（GPS/Wi-Fi/A-GPS 融合）
        │  返回 WGS-84 经纬度 + 精度半径(accuracy)
        ▼
    米级坐标到手
```

### 为什么必须是 HTTPS

浏览器对「安全上下文」有硬性要求：`navigator.geolocation` 这类**强大特性（powerful feature）**只在 HTTPS（或 `localhost`）下可用。

- **HTTP 页面** → 静默拒绝，`getCurrentPosition` 直接走 `error` 回调（`PERMISSION_DENIED` 或根本不暴露 API）。
- **HTTPS 页面** → 才允许请求定位，弹授权框。

这就是为什么任何「诱饵页」想拿定位，必须先套一层 HTTPS（哪怕自签证书）。这也是**防御方识别异常页面的第一个信号**：一个来路不明的站点突然要求位置权限。

### 坐标系：WGS-84 与 GCJ-02

浏览器返回的是 **WGS-84**（GPS 原生坐标，国际标准）。但在中国大陆，地图服务使用国测局制定的 **GCJ-02**（火星坐标），两者会有 **50–500 米**的偏移：

| 坐标系 | 谁在用 | 说明 |
|---|---|---|
| **WGS-84** | GPS、Google（海外）、浏览器 geolocation | 国际原始坐标 |
| **GCJ-02** | 高德、腾讯、Google（国内） | 加偏后的「火星坐标」 |
| **BD-09** | 百度 | 在 GCJ-02 上再加密一次 |

> 拿到浏览器坐标（WGS-84）后，要在地图上正确显示国内位置，需做 WGS-84 → GCJ-02 转换；反过来「反推真实位置」也需要理解这层偏移。这是定位研究中极易踩坑、也最能体现技术深度的点。

## 定位之外：配套指纹项

米级坐标往往不是孤立的。配合以下指纹，追踪者能构建更完整的画像：

| 类别 | 采集项 | 作用 |
|---|---|---|
| 设备 | User-Agent、屏幕分辨率、语言、时区 | 基础画像 |
| 硬件 | WebGL 渲染器、字体、电池电量/充电状态 | 设备唯一性 |
| 网络 | 内网 IP、连接类型（WebRTC） | 网络拓扑 |
| 行为 | 传感器、剪贴板、无痕检测 | 行为指纹 |

**关键认知**：单看每一项都「无害」，但**交叉关联**后，即使没有精确坐标，也能推断出你的位置（时区 + 语言 + 语言偏好 + IP 归属 ≈ 城市，加上 Wi-Fi/基站 ≈ 街区）。

## 防御方视角：如何识别与反制

理解攻击面，是为了更好地防御。识别一个「正在试图定位/追踪你」的页面：

1. **来路不明的站点索要位置权限** → 直接拒绝。浏览器地址栏会显示定位图标，点击可撤销。
2. **观察是否强制 HTTPS + 自签证书** → 陌生域名 + 证书警告 + 立即要定位，是典型诱饵页信号。
3. **检查浏览器隐私设置**：
   - iOS：设置 → 隐私 → 定位服务 → Safari 关闭
   - Android / Chrome：站点设置里禁用位置
   - 桌面浏览器：地址栏定位图标 → 一律「阻止」
4. **主动式防御**：用隐身模式 + VPN + 关闭 Wi-Fi/蓝牙，可同时抹掉 IP 归属和 Wi-Fi 定位两个维度。

**给开发者的口令**：任何前端代码里，`navigator.geolocation` 出现的位置，都值得多看一眼——它在你的产品里，是否真的有必要索取用户的精确位置？
